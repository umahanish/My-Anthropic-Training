Classic MCP vs Code Mode

The task: check the weather in all 8 office cities, pick the warmest one that isn't rainy or stormy, and book a flight there. Both flows below trace the real demo runs.

Every definition up front

Claude gets all tool schemas. With dozens of MCP servers, that alone fills the context.

Every byte through the model

All 8 full forecasts land in Claude's context, even though it needs only the temperature and condition.

The model is the loop

Each step means another model turn that re-reads the growing conversation.

# Python Code Mode: the code Claude actually wrote, the whole task in one run
offices = travel.list_offices()["offices"]
res = []
for c in offices:
    w = travel.get_weather(city=c)
    res.append((c, w["temp_c"], w["condition"]))
ok = [r for r in res if not any(k in r[2].lower() for k in ["rain","storm","thunder"])]
best = max(ok, key=lambda r: r[1])
b = travel.book_flight(destination=best[0], date="2026-11-20")
return {"all": res, "best": best, "booking": b}
One tool

Claude sees only call_tool_chain, plus TypeScript interfaces generated from the MCP tools.

Data stays in the sandbox

The loop, the fetches, and the filtering run in code, and only 8 short rows go back to Claude.

MCP is unchanged

Code Mode is an MCP client. The same travel_server.py serves both flows.
